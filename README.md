# Помощник подбора для продавца — прототип

Демонстрация для руководства. Продавец открывает ссылку **на своём смартфоне**, выбирает категорию, говорит короткую выжимку о запросе покупателя, и помощник подбирает 3–5 моделей в наличии с объяснением «почему подходит» и «в чём компромисс». Сейчас работает категория «Телевизоры». Остальные категории показаны как превью: какие вопросы будут, какой голосовой запрос и что попадёт в сравнение.

> ⚠️ Каталог, бренды, цены и остатки **вымышленные**. Прототип запускается в Google Colab, то есть в облаке Google. Для демо это допустимо, для пилота с реальными данными — только собственный сервер.

## Как пользуется продавец: диалог

Экран — это чат. Продавец **говорит** (микрофон в строке чата) или **пишет** 3–5 слов о том, что просит клиент.
Помощник отвечает **одним коротким окном**:

1. **Понял:** что запросил клиент и сколько моделей подходит.
2. **▶ Сейчас:** какую модель показать, в зале она или на складе, одна причина и честный минус.
3. **Карточки:** сразу до трёх моделей — цена, наличие, характеристики товара; под ними главная разница между первыми двумя.
4. **Предложите** — только если клиент назвал потребность («вешают на стену» → кронштейн и установка).
5. **Уточните у клиента** — 1–2 вопроса кнопками. Отметил ответ — пришло новое окно.

Сравнение, «убрать условие» и остальные модели свёрнуты в «Подробнее». Прошлые окна сворачиваются в одну строку. Кнопка «＋ Новый клиент» — слева от строки ввода.

Под последним окном три кнопки:
- **📋 Резюме** (по желанию) — готовая фраза «Правильно понимаю: нужен…? Из подходящих советую…». «👍 Клиент подтвердил» → «Перед оформлением скажите: цена и акции · гарантия · доставка…» и итог консультации. «✏️ Поправить» → продавец говорит, что изменить.
- **📱 Клиенту** — крупный экран для покупателя: что просил, чем модели отличаются, без остатков и служебного текста.
- **✅ Итог** — записать результат в журнал.

**Вопросы клиента — тоже в чат.** «OLED выгорает?», «дорого», «может подождать скидок» — помощник отвечает текстом из таблицы экспертов `data/knowledge/tv_objections.csv`. По каким словам узнавать вопрос, эксперт пишет в колонке `keywords` через «;».

## Что показать директору (5 минут)

Ссылку откройте на телефоне (экран продавца) и на ноутбуке (слева «🎬 Сценарий показа», «Под капотом», «Итоги для руководителя»). Фразы сценария продолжают диалог, как будто их сказал продавец, — показ не зависит от шума и микрофона.

1. «только не олед, 55 или 65 дюймов» → окно с моделью, в подборке нет ни одного OLED, внизу «Уточните: бюджет, для чего». Отметьте «до 70 тыс.» — новое окно.
2. «повесят на стену» → «Предложите: кронштейн, установка — вешают на стену».
3. «OLED выгорает?» и «дорого» → ответы экспертов, условия подбора не меняются.
4. «📋 Резюме» → «👍 Клиент подтвердил» → «Перед оформлением скажите…» → итог «✅ Показал, клиент выбрал».
5. «📱 Клиенту» — экран для покупателя.
6. «＋ Новый клиент», затем «65 дюймов олед до девяноста тысяч» → «мешает тип матрицы, ближайшее…». «✅ Итог» → «🚫 Нет подходящих».
7. Боковая панель: **«Чего не хватило в магазине»**, доля подтверждённых резюме, сколько фраз продавцу понадобилось на консультацию.

## Что нового: диалог (26.11.2026)

- Экран переделан в чат: одно окно на ответ, активно только последнее. Большая панель записи голоса убрана, микрофон — в строке чата.
- Новый модуль `core/dialog.py` собирает окно ответа. Он не зависит от Streamlit и проверяется тестами.
- Возражения узнаются по ключевым словам. Вопрос «OLED выгорает?» не превращается в условие «нужен OLED».
- Журнал итогов пишет, подтвердил ли клиент резюме и сколько фраз сказал продавец. Журнал старого формата откладывается в `logs/events_old_*.csv`.
- Тесты: `python -m pytest -q` → 57 passed, включая эталон из 38 фраз.

## Как устроено

```
Голос продавца ──► GigaAM-v3 (речь → текст)
Текст выжимки ──► малая модель Qwen2.5 (текст → условия JSON) ──► проверка ──┐
                  правила-регулярки (запасной разбор) ────────────────────────┤
Кнопки ──────────────────────────────────────────────────────────────────────┴─► условия
Условия + каталог + остатки ──► правила подбора ──► окно ответа: что показать, что уточнить, что предложить
Вопрос клиента («OLED выгорает?») ──► таблица экспертов по ключевым словам ──► окно с ответом
```

Модель **не выбирает товар** и не пишет тексты покупателю. Каждое условие, которое она нашла, проверяется: допустимый ли это параметр, допустимое ли значение и есть ли цитата из исходной фразы. Не прошло — отбрасывается (видно в панели «Под капотом»). Если модель ошиблась или недоступна, условия достают правила, и консультация продолжается.

| Файл | Что внутри |
|---|---|
| `app.py` | Интерфейс Streamlit: чат под смартфон, экран клиента; «Под капотом» и итоги — в боковой панели |
| `core/categories.py` | Категории: значок, готовность, вопросы, пример фразы, частые запросы, поля сравнения |
| `core/rules.py` | Вопросы, подбор, объяснения, «нет подходящих», сравнение |
| `core/knowledge.py` | Чтение таблиц знаний: возражения, сопутствующее, «не забыть сказать» |
| `core/report.py` | Итоги для руководителя из журнала: исходы, «чего не хватило в магазине» |
| `core/dialog.py` | Окно ответа в диалоге: что понял, что показать, что уточнить, что предложить, резюме |
| `core/parser.py` | Разбор выжимки: модель + проверка + правила |
| `core/asr.py` | Распознавание речи: GigaAM-v3, запасной Whisper-small |
| `core/config.py` | Настройки через переменные окружения |
| `core/prefetch.py` | Предварительное скачивание моделей |

| `tests/` | Тесты логики (`python -m pytest -q`) |

## Запуск в Google Colab

1. Загрузите эту папку в свой репозиторий на GitHub (например, `tv-assistant-demo`).
2. Откройте `colab_launch.ipynb` в Colab: *Файл → Открыть блокнот → GitHub* → ваш репозиторий.
3. *Среда выполнения → Сменить среду выполнения → T4 GPU*.
4. В ячейке 1 впишите адрес репозитория, затем *Выполнить все*.
5. В последней ячейке появится ссылка `https://….trycloudflare.com`. Откройте её сами один раз заранее — при первом открытии модели загружаются в память.

Ссылка работает, пока открыт ноутбук. Бесплатный Colab отключается после простоя, поэтому запускайте за 15–20 минут до показа.

## Запуск на своём компьютере

```bash

pip install -r requirements.txt
pip install "git+https://github.com/salute-developers/GigaAM.git"
```

Микрофон в браузере работает на `http://localhost` и на `https://`-адресах.

## Настройки (переменные окружения)

| Переменная | По умолчанию | Варианты |
|---|---|---|
| `PARSER` | `llm` | `rules` — без языковой модели, только правила |
| `LLM_MODEL` | `Qwen/Qwen2.5-1.5B-Instruct` на видеокарте, `Qwen/Qwen2.5-0.5B-Instruct` на процессоре | любая чат-модель Hugging Face |
| `ASR_BACKEND` | `gigaam` | `whisper`, `none` |
| `GIGAAM_MODEL` | `v3_e2e_rnnt` | `v3_e2e_ctc` (быстрее) |

Самый лёгкий режим для очень слабой машины: `PARSER=rules ASR_BACKEND=none` — работает без моделей, выжимка вводится текстом.

## Ограничения прототипа

- Время распознавания и разбора на T4 и на процессоре не замерено — оно показывается в панели «Под капотом» при каждом запросе.
- Запись голоса — до 24 секунд (короткий режим GigaAM).
- Категории кроме телевизоров — только превью: каталогов и проверенных правил подбора для них нет, поэтому товары не показываются.
- На iPhone микрофон работает в Safari 14.5 и новее; при первом нажатии браузер спросит разрешение.
- Журнал итогов пишется в `logs/events.csv` внутри сессии Colab и пропадает при её закрытии.
- Модели: GigaAM-v3 — лицензия MIT, Qwen2.5 — Apache 2.0.
