# Помощник подбора для продавца — прототип

Демонстрация для руководства. Продавец открывает ссылку **на своём смартфоне**, выбирает категорию, говорит короткую выжимку о запросе покупателя, и помощник подбирает 3–5 моделей в наличии с объяснением «почему подходит» и «в чём компромисс». Сейчас работает категория «Телевизоры». Остальные категории показаны как превью: какие вопросы будут, какой голосовой запрос и что попадёт в сравнение.

> ⚠️ Каталог, бренды, цены и остатки **вымышленные**. Прототип запускается в Google Colab, то есть в облаке Google. Для демо это допустимо, для пилота с реальными данными — только собственный сервер.

## Что показать директору (5 минут)

Ссылку откройте на телефоне (это экран продавца) и на ноутбуке — там слева боковая панель:
**«🎬 Сценарий показа»**, **«Под капотом»** и **«Итоги для руководителя»**. Если в кабинете шумно,
вместо голоса нажимайте фразы из сценария — они разбираются точно так же.

1. **Категории.** Нажмите «Холодильники · скоро»: «все категории устроены одинаково — новая категория это каталог и правила, а не новый экран». Затем «📺 Телевизоры».
2. **Голос.** Скажите *«шестьдесят пять дюймов, для плейстейшн, до ста тысяч»* (или нажмите эту фразу в сценарии). Появятся условия, фраза «Правильно понимаю…» и 3 модели с «почему подходит» и «компромисс». Ниже — «Предложить по потребности»: кабель HDMI 2.1 и доставка, с причиной.
3. **Отрицание.** *«только не олед, 55 или 65 дюймов»* — в подборке ни одного OLED. Под карточками — **«Уточните у клиента»**: помощник сам подсказывает, что ещё спросить (бюджет, для чего). Нажмите «до 70 тыс.» — подборка сразу пересчитается.
4. **Сравнение и экран клиента.** Включите «Сравнить» у двух моделей → таблица. Нажмите **«📱 Показать клиенту сравнение»** — крупный экран для покупателя: что просил, чем модели отличаются, честные компромиссы, без остатков и служебного текста. «← Вернуться к подбору».
5. **Консультация.** «Ответ на возражение» и «Перед оформлением: не забыть сказать».
6. **Нет подходящих.** *«65 дюймов олед до девяноста тысяч»* — помощник называет, что мешает, и предлагает ближайшие варианты. Нажмите «🚫 Нет подходящих».
7. **Итоги для руководителя** (боковая панель): число консультаций, доля «показал клиенту» и **«Чего не хватило в магазине»** — запросы, на которые не нашлось модели. Это неудовлетворённый спрос для закупки и выкладки.

**Как пользуется продавец:** категория → голос (нажал — сказал — нажал; кнопка сразу готова к следующей записи) или частый запрос → при необходимости «Уточнить вопросами» → карточки → «Сравнить» → итог. Всё в одной колонке, кнопки под палец. Магазин выбирается один раз в боковой панели (кнопка «›» вверху слева).

## Что нового в версии от 26.11.2026 и как проверить

Исправлено по результатам проверки и добавлены подсказки по стандарту консультации.

**Разбор фразы понимает больше** (проверьте голосом или текстом):

| Скажите | Что должно появиться в условиях |
| --- | --- |
| «только не олед, 55 или 65 дюймов» | Диагональ 55–65″, Не OLED — и ни одного OLED в подборке |
| «без смарта, приставка уже есть» | ничего: ТВ-приставка — не игровая консоль |
| «от 50 до 80 тысяч» | От 50 000 ₽, До 80 000 ₽ |
| «дешевле 30 тысяч», «в пределах полтинника» | До 30 000 ₽ / До 50 000 ₽ |
| «ниша 125 сантиметров» | Ширина до 125 см — самые большие модели, что помещаются |
| «для футбола» | Для: спорт — вперёд модели 100–120 Гц |
| «повесят на стену», «для PS5» | подсказка «Предложить по потребности»: кронштейн, установка, кабель HDMI 2.1 |

**Экран после запроса стал короче:** сразу условия, фраза «Правильно понимаю: …» для клиента и 3 модели.
Остальные модели — под «Ещё», текст, частые запросы и вопросы — под «Изменить запрос».

**Блок «Консультация»** (только то, что относится к клиенту):
- «Предложить по потребности» — появляется только при названной потребности, с причиной и вопросом клиенту;
- «Ответ на возражение» — выберите вопрос клиента, получите ответ по фактам;
- «Перед оформлением: не забыть сказать» — 8 пунктов стандарта; отметки по желанию, в журнал идёт их число.

**Таблица знаний для экспертов** — `data/knowledge/`:
`tv_objections.csv` (возражения), `tv_addons.csv` (сопутствующее и когда предлагать), `tv_terms.csv` («не забыть сказать»).
Тексты — черновики, их утверждает эксперт. Правка CSV не требует программиста; перезапустите приложение.

**Эталонный набор фраз** — `tests/golden_phrases.csv` (38 фраз). `python -m pytest` падает, если разобрано верно меньше 90%
или хоть одно условие перевёрнуто. Новую трудную фразу из зала добавляйте строкой в этот файл.

## Как устроено

```
Голос продавца ──► GigaAM-v3 (речь → текст)
Текст выжимки ──► малая модель Qwen2.5 (текст → условия JSON) ──► проверка ──┐
                  правила-регулярки (запасной разбор) ────────────────────────┤
Кнопки ──────────────────────────────────────────────────────────────────────┴─► условия
Условия + каталог + остатки ──► правила подбора ──► 3–5 моделей, «почему», «компромисс», сравнение
```

Модель **не выбирает товар** и не пишет тексты покупателю. Каждое условие, которое она нашла, проверяется: допустимый ли это параметр, допустимое ли значение и есть ли цитата из исходной фразы. Не прошло — отбрасывается (видно в панели «Под капотом»). Если модель ошиблась или недоступна, условия достают правила, и консультация продолжается.

| Файл | Что внутри |

## Запуск в Google Colab

1. Загрузите эту папку в свой репозиторий на GitHub (например, `tv-assistant-demo`).
2. Откройте `colab_launch.ipynb` в Colab: *Файл → Открыть блокнот → GitHub* → ваш репозиторий.
3. *Среда выполнения → Сменить среду выполнения → T4 GPU*.
4. В ячейке 1 впишите адрес репозитория, затем *Выполнить все*.
5. В последней ячейке появится ссылка `https://….trycloudflare.com`. Откройте её сами один раз заранее — при первом открытии модели загружаются в память.

Ссылка работает, пока открыт ноутбук. Бесплатный Colab отключается после простоя, поэтому запускайте за 15–20 минут до показа.

## Запуск на своём компьютере

```bash
pip install torch torchaudio            # CPU-версии достаточно
pip install -r requirements.txt
pip install "git+https://github.com/salute-developers/GigaAM.git"
# нужен ffmpeg в PATH
streamlit run app.py
```

Микрофон в браузере работает на `http://localhost` и на `https://`-адресах.

## Настройки (переменные окружения)

| Переменная | По умолчанию | Варианты |
|---|---|---|
| `PARSER` | `llm` | `rules` — без языковой модели, только правила |
| `LLM_MODEL` | `Qwen/Qwen2.5-1.5B-Instruct` на видеокарте, `Qwen/Qwen2.5-0.5B-Instruct` на процессоре | любая чат-модель Hugging Face |
| `ASR_BACKEND` | `gigaam` | `whisper`, `none` |
| `GIGAAM_MODEL` | `v3_e2e_rnnt` | `v3_e2e_ctc` (быстрее) |

Самый лёгкий режим для очень слабой машины: `PARSER=rules ASR_BACKEND=none` — работает без моделей, выжимка вводится текстом.

## Ограничения прототипа

- Время распознавания и разбора на T4 и на процессоре не замерено — оно показывается в панели «Под капотом» при каждом запросе.
- Запись голоса — до 24 секунд (короткий режим GigaAM).
- Категории кроме телевизоров — только превью: каталогов и проверенных правил подбора для них нет, поэтому товары не показываются.
- На iPhone микрофон работает в Safari 14.5 и новее; при первом нажатии браузер спросит разрешение.
- Журнал итогов пишется в `logs/events.csv` внутри сессии Colab и пропадает при её закрытии.
- Модели: GigaAM-v3 — лицензия MIT, Qwen2.5 — Apache 2.0.
